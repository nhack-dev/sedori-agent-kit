# 上級者向け運用ガイド（せどり）

このキットを「本物の運用者」として回すための段取りです。AGENT.md（毎日やること）の上に、
**数字で回す・失敗から戻す・組み合わせる**を足します。

## 1. 1週間の回し方（PDCA を数字で）
1. **仮説を書く**（1行）… 「何を変えると、どの数字が、どれくらい動くはず」。
   例）「利益が出ない → 手数料を実額で入れ直し下限値を再計算」
2. **1つだけ変える**… 同時に2つ変えると、どちらが効いたか分かりません。変えるのは1か所。
3. **同じ条件でそろえる**… 投稿の時間帯・曜日・本数など、比べる条件をそろえる（対照）。
4. **前と後を数で取る**… 主な数字（候補数・利益率(ROI)・回転）を、母数と測った日時つきで控える。
5. **当たり／外れを書く**… 外れたら「外れた」と残し、次の仮説に進む。推測で「効いた」と言わない。

伸ばす軸はまず **ROI中央値／不良在庫率** に絞ります。全部を同時に追わない。

## 2. 判断の分かれ道（迷ったとき）
- 数字が**動かない** → 変えた所が小さすぎないか。1段おおきく変えて、また1週間。
- 数字が**下がった** → すぐ元に戻す（1か所だけ変えてあるので戻せる）。戻した事実も控える。
- 数字が**上がった** → なぜ上がったかを1行で説明できるまで、横展開しない。
- **分からない** → 分からないと書いて、利用者（あなたの担当者）に判断材料として渡す。

## 3. 失敗したときの戻し方
- 送信・投稿・公開を伴う道具は、既定で「出さない（dry-run）」です。`--go` を付けて初めて外に出ます。
- 事故ったら、まず**出したものの記録**（`data/` などの控え）を開いて、何が・いつ・どこへ出たかを数える。
- 原因が100%分かるまで、追加の直しを入れない（当て推量の上書きは傷を広げます）。
- 一度に多くを流す前に、**過去数日ぶんの実データで1回試す**。その日のデータでだけ通った、を避ける。

## 4. 上級者の組み合わせ
- リサーチ → 下書き → 検査 → （あなたのOKで）実行 → 振り返り、を**1本の流れ**として毎週回す。
- `templates/` の型を、自分の勝ちパターンで増やす（例が架空なので、実データで置き換える）。
- 振り返りの数字は、翌週の仮説の材料にする。**先週の自分**を基準に比べる（他人と比べない）。

## 5. やってはいけないこと
- 門（`scripts/nhack_gate.py`）や各スクリプト冒頭の import を消す（動かなくなります）。
- 「必ず稼げる」「不労所得」などの断定（規約・法律に触れます）。
- 公式に確かめていない数字や上限を、事実として書く（必ず一次情報で確かめる）。
